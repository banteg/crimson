# player_update: three remaining compiler decisions

The retained source from `c04be5133` remains **94.8318878460%**, with
`exact=false`, `body_byte_exact=false`, 4,211/4,206 instructions and
918/0/0 clean/unresolved/mismatched references. No source change from this
investigation was promoted.

Preserving C2 probes isolate all remaining differences to three decisions.
Overriding those decisions together produces a diagnostic object with
`exact=true` and `body_byte_exact=true`. **That object is not a source match.**
It is generated by deliberate compiler-state interventions, has no matching
credit, and is not installed as a scratch object or native provider. The
canonical C++ and pinned C2.DLL are unchanged.

## Index: a global preference, not local register rotation

At native `0x413e5b..0x413e64`, the candidate loads the auto-target index into
ECX instead of EAX. The global allocator assigns range 110, symbol 333
(`target_index`), priority 32 and benefit 8. EAX is allowed. However, its
preferences include ECX with weight 1 and EDI with weight 4; EDI is unavailable.
The chooser costs are EAX=0, ECX=-1, EDX=0, EBX=2001 and EBP=1. ECX wins.

The address-expression range 573 is colored ECX first, with priority 42.
A later scoring pass adds the index's ECX preference at `0x10724fc7`, the
LEA-base preference path. Clearing only that preference at the chooser fixes
exactly the three index instructions. It does not fix the other regions.

`chooser_trace.py` records allowed sets, preferences, uncolored neighbors
and the actual cost array at the chooser's return. Its observer preserves
the entire COFF object after clearing only the timestamp. The separate
preference-call trace identifies the LEA scoring callsite.

## Firing flag: pressure while coloring a duplicate address range

Native keeps `normal_fire_ready` in BL from `0x415741` through `0x41590e`.
The candidate spills it and reloads BL at the firing condition.

The long flag range 157, symbol 1708, has priority -5 and benefit 8. The swap
block contributes -18 to that priority. This penalty alone does **not**
explain the spill: another source control colors the long range at priority
-2, and adding 8, 16, 24 or 32 to the baseline priority leaves the spill
unchanged.

The decisive interference walk colors range 664, symbol 5640: a temporary
holding `&player->shot_cooldown`, live across blocks 318..330. It has priority
39 and benefit 6. The named cooldown pointer and this temporary coexist
during interference analysis, before later copy folding. The walk places
pressure split markers at calls and swap instructions. After constraint
processing, the flag's flags word changes from `0x28c02` to `0x28e02`, setting
the pending-split bit. The original range is replaced by the shorter range
773, which is eventually colored BL.

Removing just range 157 from that address range's pending split set recovers
the complete native flag region while preserving the swap instructions.
Calling `pu_swap` through `*shot_cooldown` also avoids the spill in ordinary
C++, but removes native's `mov ecx, ebp` pointer copy and changes later
register choices. Explicit field pointers, partial swap expansion, exchange
helpers and nested weapon-state views likewise give neutral results or
trade one discrepancy for others.

## Demo angle: the block mover's 20-byte clone threshold

At native `0x414d02`, the original jumps to the shared angle tail at
`0x414d42`; the candidate duplicates four floating-point instructions.
The earlier [arithmetic investigation](../player-update-arithmetic-2026-09-27/README.md)
records the block mover's estimates: `3, 0, 3, 0, 2, 0, 6, 5`, totaling
19 bytes including the terminating jump. This is below the `/Ot` threshold
of 20 bytes. The zero-size nodes are rounding markers.

Making the demo FPATAN estimate (C2 line 587) exceed the threshold prevents
the clone and fixes exactly this region. Other angle estimates are untouched.
The final emitted ESP/SIB encodings are not the size
estimate used by the earlier mover pass. Changes to vector copy operations,
argument passing, angle helpers, out parameters, temporary scope, result
type, return-value construction and branch-local angle computation did not
recover the native tail without other losses.

## Source and option controls

`controls.json` records **78 additional source variants** and four compiler
option controls as reversible edits to the pinned `baseline/scratch.cpp`.
Each entry includes its source hash, all four scores, instruction counts
and reference audit. These are compiled variants, not 78 independent theories.

The source controls cover pointer/reference and member-pointer swaps,
exchange helpers, typed overloads, return types, calling conventions,
partial swap expansion, named field pointers, inline ready predicates,
index reuse/accessors, vector copy construction/assignment, member and
out-parameter angle helpers, argument passing, demo branch structure and
temporary scope. The two adjacent 28-byte weapon records also received
typed-owner controls. None was retained.

`/GX` and `/Ob1` are neutral for this baseline. `/Op` and `/Oa` produce large
regressions and reference problems. The earlier MSVC6 SP6 control was also
neutral. There is no evidence here for changing the canonical compiler or
options.

One inline-predicate control increases the raw score to 94.8918983131%, but
adds a non-native branch and leaves six excess instructions. This is a score
tradeoff, not a recovery. The supported lifetime, helper, owner-layout and
tail-shape hypotheses in these two investigations are exhausted; the source
origin of the three decisions remains unresolved.
